# 规格：offline-experience-resilience

> 产品目标、ADR-0052 和末尾追加预览于 2026-10-05 获项目所有者确认；模块已纳入能力图并激活。导航重试与默认页有界恢复已实现；十包 0.4.0 已发布并完成公开消费验证，OE5 剩余环境与 R1 宿主验收继续保留，PRE 未部署。

## 目标

改善导航兜底与默认离线页的弱网体验：短暂读取失败不立即展示整页离线提示；响应超时有准确反馈；自动恢复不因 worker 可达而反复重载不可用的业务页面。

依据：[设计记录](proposals/offline-experience-resilience.md)、[优化前边界证据](../docs/review/2026-10-05/offline-experience-boundaries.md)。这是现有平台包的独立优化迭代，不新增运行时 NPM 包。

## 已确认的范围

1. 适用的导航文档读取提供有界重试或宽限，不因一次短暂失败立即整页兜底。
2. 保留长等待出口；超时或网络请求失败的默认提示不直接断言设备已离线。
3. 恢复判定更接近原业务入口可用性，并通过退避、冷却和跨重载预算阻止恢复循环。
4. 平台实现、自动化与真实浏览器验证、候选包消费验证及宿主升级说明共同构成交付。

不承诺“设备有网络就永远不显示兜底”：网络连接状态不能证明源站、文档或业务服务可用。不以无限等待来满足这一表述。

## 优化前基线与修复目标

| 位置 | 已核实行为 | 需要改进 |
| --- | --- | --- |
| `packages/sw-runtime/src/worker/handlers.ts` 的 `navigate()` | 请求提前失败即兜底；显式阈值内无响应头也兜底；4xx/5xx 原样返回。 | 短暂失败宽限、明确的等待预算及兼容语义。 |
| `packages/vite/src/offline-page.ts` | 默认文案断言离线；可见页面每 10 秒 HEAD worker 文件，3 秒超时，一次成功重载。 | 准确提示、入口可用性判定、有界恢复。 |
| 优化前受控浏览器验证 | 4 秒文档正常；6 秒文档显示离线页；不足 1 秒失败窗口立即兜底；业务失败而 worker HEAD 成功时约 10 秒循环重载。 | 形成仓库回归用例，不能仅修正文案或增大阈值。 |

## 安全与兼容边界

- 不改变 `PwaIdentity`、SW URL/scope、manifest ID、缓存命名空间及更新确认接管协议。
- 不放宽私有、会话、写入、流式、跨 Origin 和未分类请求的缓存准入；本迭代不增加业务缓存写入。
- 重试只作用于经规则允许的同源导航文档 GET。API、媒体、写请求和非文档请求不加入平台全局重试。
- 重试不能在前一请求仍挂起时并发发出同一导航；有响应的 4xx/5xx不按网络读取失败重试，不以旧业务内容掩盖错误。
- 不根据 `navigator.onLine` 的单一值确认设备离线或确认业务恢复。
- 新公开字段、计划注入、worker 协议或持久状态必须先有 ADR 与校验；不在实现中临时添加未经记录的公开选项。
- 既有 `networkTimeoutSeconds` 同时用于导航和 network-first 运行时缓存。本迭代不得顺带改变运行时缓存的超时、命中原因和晚到写入语义。
- 短暂失败宽限与旧策略行为的冲突必须显式解决。OE1 优先评估显式启用的导航专用策略；默认离线页的安全恢复修正和文案修正记录在升级说明中。不可宣称所有旧构建无需升级即可获得修复。
- 业务自带离线页不被生成器覆盖；接入说明给出其需要自行对齐的恢复要求。

## 行为要求

### 导航失败和等待预算

推荐契约见 [ADR-0052](../docs/adr/0052-offline-experience-resilience.md)：显式 `navigationRetry.delayMilliseconds`，100–3,000 ms，至多一次额外串行请求，共享 `networkTimeoutSeconds` 从首次请求开始的总预算。要求同时配置超时且延迟小于总预算；字段缺省保留旧行为。首次等待与重试不分别获得新的完整预算。OE1 已冻结此契约；验证结果见本模块 verification。

1. 正常网络文档在约定预算内到达，返回网络文档，保留路径、查询参数和响应语义。
2. 第一次读取失败且仍有重试预算时，等待有限宽限再串行重试；次数和总时间均受限。停止条件包括预算耗尽、取得响应和导航生命周期结束。
3. 网络请求仍挂起时不以“重试”制造并发请求；到达约定总预算后，按既有回退规则取得可用提示页。
4. 兜底不存在或查找失败时遵守既有原则：不把原本可能成功的请求仅因超时变成错误。失败后的最终错误仍准确返回。
5. 及时返回的 4xx/5xx不转成设备离线页；已打开页面中的 API/图片失败不整页替换。
6. 计时器、晚到响应和拒绝均收束，无额外缓存写入、未处理拒绝或脱离生命周期的无限重试。

### 提示与手动操作

- 默认标题和说明采用能覆盖网络失败、源站不可达及慢响应的文案，例如“暂时无法连接”；不能把“超时”直接描述成“当前处于离线状态”。英文与中文同步。
- 手动重试保持明确可见；禁止承诺页面一定会自动恢复。达到自动恢复预算后，用户仍可主动重试。
- 保留现有 class、CSS 变量、消息覆盖及无脚本可读性；生成脚本变化同步生成对应 CSP hash，不要求关闭 CSP。
- 短时间连续点击手动重试不得形成并发请求或多次自动重载。用户的明确手动行为与自动恢复计数分别定义，不通过自动过程伪造“用户重试”。

### 自动恢复

1. worker 文件可达仅是辅助信息，不是业务可用的充分条件。
2. OE1 明确原导航入口或显式同源只读探测入口的选择、路径和查询参数处理。探测必须取得真实网络结果，不能因 SW 兜底或缓存命中而判断“业务已恢复”。
3. 明确响应状态、类型、重定向和成功阈值；不跟随到跨 Origin 后将其判为成功，不读取、持久化或记录业务响应内容及敏感查询参数。
4. 探测有超时、串行执行，失败后退避；online 事件只是请求一次受限探测，不能绕开冷却、并发与次数限制直接重载。
5. 自动重载预算必须跨默认离线页重载有效。页面本地变量重新初始化、再次收到离线页及 worker HEAD 成功均不得自动清空失败预算。
6. 只有明确的成功恢复判据或用户主动操作才能按规则开启新恢复周期；不得通过短 TTL 无条件循环重置预算。OE1 明确成功判据与重置责任。
7. 无法安全保存或读取预算时降级为手动重试，而不是退化成无限自动恢复。
8. 页面隐藏时不探测、不重载；重新可见后也遵守冷却。预算耗尽停止自动重载，不因后台定时器或事件反复触发绕过上限。

## 测试剖面与验收矩阵

下列数值是明确的测试输入，不是尚未冻结的产品默认值。OE1 不能为了让实现通过而删除反向用例。

| ID | 测试输入 | 必须观察的结果 |
| --- | --- | --- |
| OE-A1 | 正常文档及文档延迟 4 秒，在已配置等待预算内 | 返回网络文档，无兜底，记录真实请求数和 elapsed。 |
| OE-A2 | 连接失败窗口 900 ms，重试延迟测试值 1 秒，至多一次额外请求，总预算测试值 5 秒 | 后续读取成功，不出现整页兜底；平台额外请求不超过 1 次。浏览器内部重试单独计数。 |
| OE-A3 | 持续连接失败，使用同一重试剖面 | 预算内进入可用提示页，不能无限等待或无限重试。 |
| OE-A4 | 文档延迟 6 秒：分别配置 5 秒与 10 秒预算 | 10 秒剖面正常返回文档；5 秒剖面提供暂时不可用提示，不能断言设备离线。 |
| OE-A5 | 响应头在阈值前、等于阈值及阈值后到达；响应体随后挂起 | 冻结竞争规则，记录等待限制作用范围；不得声称文档超时覆盖全部响应体或业务加载。 |
| OE-A6 | 首次网络挂起、超时后迟到成功或迟到失败 | 不发并发重试，无未处理拒绝或额外缓存写入。 |
| OE-A7 | 无回退、回退查找失败、首次未受控制、排除路由、根/子路径、查询参数 | 保留原有可达性及排除语义，不伪造不存在的兜底保障。 |
| OE-A8 | 文档返回 404/500、API 503、图片失败 | 保留各自响应或业务异常，不进入全局重试／整页离线。 |
| OE-R1 | worker HEAD 200，业务文档持续连接失败，观察至少 60 秒 | 不因 worker 可达而自动重载，不复现约 10 秒循环。 |
| OE-R2 | 恢复探测 4 秒才返回，测试超时值 3 秒；另有 404/500、跨源跳转及兜底响应 | 不将这些结果判为恢复；探测最大并发为 1。 |
| OE-R3 | 探测偶发成功一次随后失败 | 达到评审的成功阈值前不重载；失败按退避策略处理。 |
| OE-R4 | 探测满足成功判据，但重载后的文档继续失败；测试自动重载上限 1 次，观察至少 60 秒 | 最多 1 次自动重载，预算跨重载保留，随后保留手动操作。 |
| OE-R5 | 预算状态读取／写入不可用、无 controller、脚本被 CSP 阻断 | 失败关闭自动恢复；提示与手动重试边界准确，不无限自动重载。 |
| OE-R6 | 连续 online 事件、页面隐藏/重新可见、快速多次点击、后退/前进与多标签 | 不绕过冷却或预算，不相互污染，不抢占已打开业务页。 |
| OE-C1 | 新策略未开启的旧配置，以及当前公开策略版本 | 兼容规则按 ADR 固定，有可比产物和行为，不暗中扩大准入。 |
| OE-C2 | 自带离线页、默认中英文/主题、严格 CSP、更新等待与接管 | 既有公开样式和覆盖契约兼容，生成 hash 有效，更新流程不回归。 |
| OE-P1 | 候选 NPM tarball 安装到隔离宿主；旧 worker 升级到新构建 | 验证真实发布内容及接管后的新行为，不把源码测试等同包升级通过。 |

先运行确定性的 fake-clock 单元与服务端可控浏览器夹具，再按既有浏览器矩阵验证。真实网络丢包、真机、独立窗口与现场部署证据分别记录，缺失即未验证；不能使用模拟连接关闭替代真实丢包证据。

## 依赖与交付

计划依赖：contracts-foundation、policy-compiler、network-timeout、sw-runtime、vite-adapter、browser-test-harness、package-distribution。新增策略要求 contracts/core 校验与编译，已据此重新生成 [插入预览](../docs/review/2026-10-05/offline-experience-insertion-preview.txt)。默认离线页直接消费 worker 消息，不新增 client-runtime 业务页事件。

必须交付：

- 经评审的 ADR，增补 ADR-0038 和 ADR-0036；新公开协议若涉及客户端生命周期，还需对齐 ADR-0013。
- 实现、回归测试、边界记录及浏览器结果；已确认问题、已修复范围和未验证项分别列出。
- 文档与升级说明：平台包、宿主配置、重新构建、旧 worker 接管、CSP、业务自带离线页的限制。
- 候选包的依赖闭包、tarball 消费验证及版本建议。不预先固定发布版本号；实际 NPM 发布和宿主部署单独按既有发布门禁推进。

## 实施前检查点 OE1

冻结以下决定并记录 ADR 后，再修改运行时代码：导航专用策略的公开形态及兼容方式、预算与缺省值、探测方式和准入、成功阈值、跨重载预算保存及重置、状态不可用时的手动降级。需要扩大依赖或改变已确认范围时，先展示影响，不隐式推进。

正式能力图位置仍为 `end`。普通追加因当前 `cloudflare-test-deployment` 做到一半而被拒绝；核实其剩余 5 项含外部设备前提及所有者暂缓项后，已生成只读 `--interrupt` 预览：能力图末尾追加新模块，已有顺序不变，旧模块 41/46 项待办保持原状，随后需要显式切换 activeModule。该排期预览已经项目所有者确认并执行，新模块已激活；这不代表 Cloudflare 模块已完成。
