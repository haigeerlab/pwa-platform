vue-vben-admin PWA 分析

vben 实现了哪些 PWA 能力，我们平台能从中学到什么，以及它能否用我们的平台快速接入并获得 PWA 全功能。

vben df014ae（2026-09-13）· 平台 feat/ssr-adapters 4e1676d · 只读源码分析，“需实测”条目未经浏览器验证 · 2026-09-18 · 已补真实接入试验，见试验结果

结论

  • vben 的 PWA 基本是空壳：默认关闭；开启后也不预缓存、无运行时缓存、不注册 Service Worker，只剩一份 manifest。
  • vben 真正值得借鉴的是与 SW 无关的“新版本检测”组件。
  • vben 能接入我们的平台：Vite 8、Vue 3.5、配置合并均匹配，接入后获得安装、预缓存、离线页、受控更新、私有数据默认拒绝缓存、恢复 worker。

但“快速 + 全功能”目前做不到

快速：平台包全部 private、未发布，外部项目无法直接安装，这是第一阻断项。

全功能：运行时缓存、Push、后台同步、Badging、分享目标、manifest 增强字段均未实现，分别在 v1.1 / v2 / v3 路线图或尚未规划。

vben 的实现细节

vite-plugin-pwa 接入

  • vite-plugin-pwa ^1.3.0，定义在 internal/vite-config/src/plugins/index.ts:174-188。
  • 默认 injectRegister: false、workbox.globPatterns: []，应用侧从不覆盖。插件源码表明此时只注入 manifest 链接，不注入注册脚本。
  • 开关 VITE_PWA：所有 .env.production 均为 false，仅 CI 部署时用 sed 为 4 个应用改为 true。
  • 生产路由为 hash 模式。文档站另有一套独立、较完整的 PWA 配置。

新版本检测组件（非 SW）

  • packages/effects/layouts/src/widgets/check-updates/check-updates.vue，默认开启。
  • 每分钟 HEAD 请求首页，比较 ETag / Last-Modified；页面回到前台立即检查；localhost 跳过。
  • 发现变化弹出不可关闭的对话框，确认后 location.reload()。
  • 用户可在偏好设置中关闭。

平台值得学习与参考的地方

参考点vben 的做法对平台的启示
主动版本探测HEAD 比对 ETag，前台可见时检查浏览器主要在导航时检查新 worker，单页后台长时间不刷新就发现不了新版本。建议 client-runtime 提供可选的“主动检查更新”（按间隔及 visibilitychange 调用 registration.update()），不改变 prompt 语义。
更新提示 UI 归应用对话框、文案、间隔由布局与偏好设置控制与 ADR-0013 一致；可在示例中提供后台布局风格的提示组件参考。
构建开关VITE_PWA 控制插件启用可考虑官方的构建期关闭方式，便于灰度与排障；关闭时必须能发布恢复 worker。

反面参考（平台已规避或应在文档中强调）

  • 半开启：生成了 sw.js 却不注册、不预缓存，团队误以为“已有 PWA”。接入文档应明确“未调用 register() 即无 PWA”。
  • start_url 不跟随部署路径：平台由 PwaIdentity 统一推导，已规避。
  • 图标外链第三方 CDN：平台要求图标随构建产物发布，已规避。
  • 靠 CI sed 开启：行为不在版本库中，难以追溯；平台身份与策略写在代码里。

接入步骤

  1. 保持 VITE_PWA=false，删除 CI 中的 sed。
  2. 安装 @pwa-platform/vite、@pwa-platform/vue（前提：平台已发布）。
  3. 在 vite.plugins 中加入 pwa({ identity, policy, install, topology })：scope 与 VITE_BASE 一致；为 js/、jse/、css/ 等产物目录声明 asset 规则；接口前缀声明为 session-data / mutation；配置离线页。
  4. 图标放入 public/。
  5. app.use(createPwa({ config }))，布局中调用 usePwa().register()。
  6. 把 applyUpdate() 与 check-updates 对话框合并；登出调用 logout()。
  7. vite build + vite preview 验证，Chrome 桌面与 Android 验收。

接入后仍缺的“全功能”

  • 运行时缓存：字典、菜单等公共只读数据无法离线（v1.1）。
  • Push：工单、审批提醒无法推送（v2）。
  • 离线写入：表单无法离线提交（v3）。
  • Periodic Sync、Badging：未规划。
  • manifest 增强字段：无快捷方式、截图、分享目标。
  • 自动更新与主动检查更新：未提供。
  • 同源多应用子路径：v2 topology。

建议

  1. 先发布平台包，再把 vben 作为接入样本。定义最小发布形式（私有 registry 或 git tag）。
  2. （已完成，ADR-0020）为 client-runtime 规划“主动检查更新”。后台应用的刚需，不涉及身份与缓存命名空间，需先写规格。
  3. （已完成，迁移指南）接入文档补“从 vite-plugin-pwa 迁移”。覆盖关闭原插件、产物目录规则、hash 路由、合并已有版本检测。
  4. （已完成，见下节）用 vben 做一次真实浏览器验收，确认 hash 路由离线降级、大体积产物的预缓存安装耗时与成功率、两套更新提示同时出现时的交互。
  5. 对外按路线图分期说明“全功能”。当前可承诺的是安全 PWA 基线；公共数据缓存在 v1.1，Push 在 v2。

真实接入试验结果（2026-09-18）

vben df014ae 的 apps/web-antd 接入平台 main（25d927d）构建出的 Vite 插件与 Vue 绑定，在本机 Chrome 153.0.8010.50 中验证。平台代码未做任何修改。

场景结果要点
A. 按源码现状接入，断网启动失败根目录的 _app-config-*.js 没有被预缓存，断网时页面一直停在启动动画
B. 配置文件移到 config/ 并加规则通过断网时首页与 hash 路由都能完整渲染登录页
C. 更新通过手动与 60 秒自动检查都能发现新版本；确认后新 worker 接管，页面未被重新加载
D. 私有数据通过缓存里只有静态资源；跨源接口与同源 /api 都没有被接管
E. 可安装性发现缺口Vite 插件不注入 <link rel="manifest">，要由应用手写；补上后满足安装条件
  • 预缓存规模：215 个条目，约 3.77 MB；本机回环地址上首个 worker 激活用时约 1.3–3.4 秒。
  • 测试方法上的坑：带指纹的资源返回 immutable，浏览器 HTTP 缓存会掩盖没被预缓存的文件；离线验证前必须先清空 HTTP 缓存。
  • 仍未验证：真实安装流程、旧 vite-plugin-pwa 缓存残留、Chrome Android。
  • 待决定的平台输入：Vite 插件是否自动注入 manifest 链接（已实现，见 ADR-0022）；是否支持根目录下带哈希的单个文件。
