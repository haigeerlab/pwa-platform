管理层附录 · PWA 试点

试点可行性与投入说明

回答“能不能做、先解决什么、谁来负责、什么时候才适合承诺上线”。

建议：条件式批准试点

采用“PWA 平台基线 + x9-web-pc 试点”的方式推进。x9 的技术基础匹配第一期目标，但当前不宜承诺为即插即用的接入项目。

现在可以批准方向；具体上线日期和人力，待 x9 的构建、部署与缓存边界完成核验后再确定。

当前关键前提

先通过 P0 上线门槛。

若生产等价构建、服务器缓存规则或发布边界不能稳定确认，不把问题带入 PWA 上线。

为什么 x9 适合做试点

适合的原因

  • Vue 3 + Vite，符合平台第一期支持范围。
  • 已有 PWA 与 Worker 尝试，不是从零开始。
  • 首页页面框架、赛程、资讯适合做弱网入口与离线提示。

必须接受的边界

  • 首页中的直播区、直播页、实时比分和聊天室必须联网；离线时不显示过期的“直播中”状态。
  • 登录、个人中心、上传与私有接口始终走网络。
  • 服务器响应头、CDN 与回滚流程需运维共同确认。

接入前必须通过的门槛

优先级必须确认或解决的事项责任方
P0生产等价构建稳定通过；当前本地二次构建失败有可重复、可修复的结论。x9 前端
P0补齐应用安装信息与图标，明确用户可安装的产品身份。x9 产品 + 前端
P0应用版本与每次发布联动，避免新版本仍使用旧缓存。平台 + x9 前端
P1只允许页面框架与经批准、带时效标识的公共内容快照离线展示，且不含“直播中”、实时比分等实时状态；账号、支付、直播视频、私有数据和写操作一律不缓存。产品 + 平台
P1确认首页、应用脚本与静态资源的服务器缓存规则。运维 + x9 前端
P1在真实浏览器中验证安装、断网、更新、登出后的缓存清理；断网时首页不白屏，直播区不无限 loading，而是明确提示“需要网络”。平台 + x9 前端

第一期的责任分工

平台负责提供

  • 统一的安装、离线提示、更新和缓存安全规则。
  • 将首页拆为“可离线展示的页面框架与公共快照”和“必须联网的直播/实时区域”。
  • 上线前检查与真实浏览器验证方法。
  • 面向 Vue/Vite 的接入方式和可审计报告。

x9 仍需负责

  • 选择值得弱网支持的公共页面和离线文案。
  • 修复自身构建、部署和业务接口问题。
  • 为首页直播区提供离线状态文案；不得展示过期的“直播中”状态，也不得无限 loading。
  • 与运维确认响应头、CDN 和回滚流程。

投入方式与验收

  1. 上线准备：完成 x9 P0 门槛核验；若基础构建或部署不稳定，暂停上线。
  2. 试点接入：首页仅离线展示页面框架与经批准、带时效标识的公共快照，不包含“直播中”、实时比分等实时状态；赛程、资讯按时效展示缓存内容。首页直播区、直播页和私有页面始终联网，断网时明确提示“需要网络”。
  3. 效果复盘：以安装用户回访率、弱网核心页可打开率、更新中断率和缓存事故数决定是否扩大范围。

建议管理层确认

  1. 批准 x9 作为条件式试点，先完成 P0 上线准备。
  2. 第一期按“可靠与安全优先”验收，不以离线直播、系统通知为阶段目标。
  3. 指定 x9 前端、产品和运维责任人；P0 核验后再审定排期与投入。
