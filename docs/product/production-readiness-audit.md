# PWA Platform 生产就绪审核

审核日期：2026-09-27。代码基线：`7f5d0f8a4eb93c7bd907a364d1f09f853bf01a99`。npm 基线：十个公开包 `0.1.0`，核查时 `latest` 均指向 `0.1.0`。

## 结论

**PWA Platform 的十个 `0.1.0` 包已达到“可供 Vite + Vue/React 项目采用，并以桌面 Chrome 通道继续做业务宿主生产验收”的状态；尚不应对外宣称 Android、iPhone 或所有浏览器的全功能生产门禁已经通过。**

这个结论分开了两件事：

- **库包生产就绪**：十包构建、类型、测试、Chrome 桌面 N/N-1、打包、完整性读回和独立消费已经通过，`desktop` 通道成立。
- **业务应用生产就绪**：每个接入项目仍须在自己的 Origin、路径、响应头、身份基线、旧资源保留、更新、离线和恢复流程上完成门禁。安装 npm 包不会自动完成这一步。

Android 和 iPhone 已有大量真机结果，足以证明渐进兼容和发现平台差异；但 Android 缺 N/N-1 两机，iPhone 没有独立发布通道，且存在恢复联网后的注册状态差异，因此只能标为“部分通过”。

## 已满足的生产基础

### 安全默认值

- `PwaIdentity` 的生产字段不可作为普通版本配置漂移。
- 业务声明 `PwaPolicy`，不能注入任意 Service Worker 或 Workbox callback。
- 私有数据、写操作、流媒体、带授权请求和未分类请求默认只走网络。
- 公共读取缓存必须使用 PwaPolicy v3 显式开启，只接受同源公共 GET，并受容量、时效、MIME、`Vary` 与 `Cache-Control` 准入约束。
- 恢复 worker 只清理当前应用命名空间，入口恢复不跨 Origin 延续会话、缓存或身份。

### 发布与回退

- 构建校验覆盖身份、计划、manifest、worker、必要资产和关键响应头事实。
- 十包按照依赖顺序发布，registry 读回和独立安装消费已经完成。
- 桌面 Chrome N/N-1 的安装、更新、离线和恢复证据已经取得。
- 项目提供恢复 worker、入口恢复、发布记录和事故 Runbook，但采用方必须在自己的部署环境演练。

### 更新与离线语义

- 新 worker 先安装并等待；用户确认后才接管。
- 接管不会替换当前页面 JavaScript；页面刷新由业务或默认 UI 显式触发。
- 离线能力只覆盖已取得的应用壳、声明资源和可选离线页，不代表所有路由与 API 自动可用。
- `vite dev` 不生成平台 worker；离线和安装验收必须使用生产构建与 HTTPS。

## 生产使用前必须由接入项目完成

1. 固定生产 identity、Origin、mount path、scope、worker URL、manifest URL 与缓存命名空间种子。
2. 证明所有运行时缓存规则只覆盖真正公共、与用户身份无关的同源 GET；可能写 Cookie 的响应同时设置 `Cache-Control: private`。
3. 在真实 HTTPS 部署核对 worker、manifest、HTML 和指纹资源的响应头。
4. 以真实 v1→v2 验证等待、稍后、用户确认接管、未保存数据保护和显式刷新。
5. 清除 HTTP cache 后验证断网冷启动、未缓存导航、恢复联网和恢复 worker。
6. 验证旧资源保留、回滚、事故恢复和多应用同源时的 scope 隔离。
7. 按自身支持的平台取得真机证据；不能用本仓示例或模拟器替代业务应用结论。
8. 建立自己的性能预算、可访问性测试、监控、SLO 和事故告警。

## 阻止更宽泛生产声明的事项

| 事项 | 影响 | 解除条件 |
|---|---|---|
| Android 缺 N/N-1 两机 | 不能声明 `desktop+android` 通道通过 | 按浏览器证据规则取得两台实体设备和完整必测场景 |
| iPhone 无发布通道且有注册状态差异 | 不能声明 iPhone 全功能生产保证 | 定义 Apple 平台门禁，定位/接受注册差异并完成必测矩阵 |
| 性能无预算 | 不能声明性能达到生产目标 | 定义可重复的包体、启动、安装和运行时预算并持续执行 |
| 可访问性门禁不完整 | 不能声明完整 WCAG 合规 | 补自动化与辅助技术验证，记录例外 |
| README 与接入信息不完整 | 开发者可能误接入或误判能力 | 完成本模块的十包 README、首页矩阵和功能接入路径 |

## 证据解释规则

“代码实现”“自动化通过”“真机观察”和“发布门禁通过”是四种不同结论。首页和 README 使用的所有状态都受[本模块证据索引](../../tasks/production-readiness-documentation/evidence.md)约束；原始逐场景记录以[正式版验收记录](../../tasks/stable-release-qualification/verification.md)和[0.1.0 发布记录](../../tasks/stable-release-qualification/release-0.1.0.md)为准。

本报告不修改原始测试记录，也不把文档整理本身当作新的浏览器通过证据。
