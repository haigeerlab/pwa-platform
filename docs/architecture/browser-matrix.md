# 浏览器矩阵

本文规定真实浏览器验证在哪些浏览器上进行、哪些结果阻塞发布，以及结果怎么记录。[V1 验收矩阵](v1-acceptance-matrix.md)中需要真实浏览器证据的场景，都按本文的范围执行。

## 分档

| 档位 | 浏览器 | 版本 | 结果是否阻塞 |
|---|---|---|---|
| 必测 | Chrome 桌面端、Chrome Android | 稳定版渠道的 N 与 N-1 | 阻塞：任一场景失败，质量门禁或发布门禁即失败。发布门禁中的阻塞范围按下文的发布通道确定 |
| 参考 | Edge 桌面端 | 稳定版渠道的 N | 不阻塞：失败需登记 Issue |
| 渐进兼容 | Safari（macOS、iOS）、Firefox 桌面端 | 验证时的当前稳定版 | 不阻塞：差异写成兼容性说明 |

- **N 与 N-1。** N 是验证当天该浏览器稳定版渠道的最新主版本，N-1 是它的上一个主版本。两个版本都要跑完同一组场景。
- **必测覆盖两个平台。** Chrome 桌面端和 Chrome Android 分别计算，一个平台通过不能代替另一个。本次发布要求哪些平台，由下文的发布通道决定。
- **Chrome Android 的 N-1 怎么获得。** 应用商店只提供最新版本，因此准备两台关闭自动更新的测试设备，只通过 Google Play 更新，不从其他来源安装 APK。新的稳定版发布后，只把当前处于 N-1 的那台升级到新版本，原来处于 N 的那台随之成为 N-1。拿不到 N-1 时，这一项按未通过处理，不设例外。
- **参考档。** Edge 与必测档跑同一组场景。失败不阻塞，但要登记 Issue，并在验证记录中写上 Issue 链接。
- **渐进兼容档。** 安装与 Push 不做保证。离线启动和更新行为与必测档不同时，写成兼容性说明（见下文）。无论哪项能力不可用，基础 Web 体验都必须可用。

## 发布通道

每次生产发布必须声明通道（[ADR-0030](../adr/0030-desktop-release-channel.md)）：

| 通道 | 阻塞发布的必测范围 | Chrome Android 在证据中的状态 |
|---|---|---|
| `desktop` | Chrome 桌面端的 N 与 N-1 | 填写"不在本通道"：既不算通过，也不算未执行 |
| `desktop+android` | Chrome 桌面端与 Chrome Android，各自的 N 与 N-1 | 按必测规则填写 |

- 两个通道对 Chrome 桌面端的要求完全相同，`desktop` 通道不降低任何一项。
- 以 `desktop` 通道发布后，在首次以 `desktop+android` 通道发布之前，Chrome Android 未经验证、不做任何保证（包括基础网页体验），对外不得声称支持 Android。
- 通道在发布尝试创建时确定，之后不可更改；"不在本通道"只允许用于 `desktop` 通道的 Chrome Android 行（ADR-0030）。
- 桌面端 N-1 可以使用 Google 官方的 Chrome for Testing 构建，通过 `PWA_HARNESS_CHROME_PATH` 运行（ADR-0010）。
- 参考档与渐进兼容档的规则不随通道变化。

## 检测原则

沿用[兼容性策略](compatibility.md)中的原则：使用特性检测，不做浏览器嗅探。

- 运行时代码只根据特性是否可用决定行为，不读取 User-Agent 来分支。
- 测试断言同样以特性是否可用为准：某项能力在该浏览器上不可用时，断言降级行为成立，而不是按浏览器名称跳过场景。
- 档位只决定一个结果是否阻塞发布，不改变运行时行为。

## 版本号

本文只写规则，不写具体版本号。每次验证都把实测环境写进验证记录，至少包含：

| 字段 | 内容 |
|---|---|
| 浏览器与档位 | 例如 Chrome Android（必测） |
| N / N-1 | 本次对应的是 N 还是 N-1 |
| 完整版本号 | 浏览器报告的完整版本号 |
| 操作系统 | 名称与版本；Android 与 iOS 另写设备或模拟器型号 |
| 日期 | 执行验证的日期 |
| 结果 | 逐场景的通过或失败；失败附日志或 Issue 链接 |

验证记录放在执行验证的模块的 `tasks/<module-id>/verification.md` 中；生产发布时使用[生产发布浏览器证据](../operations/browser-release-evidence.md)记录同一发布尝试的完整平台、版本、场景与证据。该模板中的“未执行”或缺少字段均不构成通过。

真实浏览器验证使用 [browser-test-harness](../../packages/browser-test-harness/README.md)：每个测试把浏览器版本写入 `browser-version` 注解，并在日志中打印实际运行的版本；桌面端 N-1 的运行步骤见其 README。Chrome Android 的运行方式尚未确定，由第一个具备测试设备的运行时模块在其规格中决定（[ADR-0010](../adr/0010-real-browser-verification-with-playwright.md)）。

## 兼容性说明

渐进兼容档的已知差异，按下表记录在验证记录的"兼容性说明"一节中：

| 字段 | 内容 |
|---|---|
| 浏览器与版本 | 浏览器、完整版本号与操作系统 |
| 场景 | 对应 V1 验收矩阵中的哪个场景 |
| 观察到的差异 | 与必测档相比，实际行为有什么不同 |
| 对用户的影响 | 基础 Web 体验是否仍可用，用户会看到什么 |
| 跟踪 | 相关 Issue 链接；上游浏览器问题也写上链接 |

同一差异在后续验证中仍然存在时，更新原记录中的版本号，不重复登记。差异消失时，在记录中注明从哪个版本起不再出现。
