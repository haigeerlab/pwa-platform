# ADR-0039：可选的默认更新提示

## 状态

已接受（2026-09-26，项目所有者要求继续默认 UI 工作）。

## 背景

ADR-0005 与 ADR-0013 把更新提示的展示留给应用。现有 Vue/React 示例有完整流程，但它们的内联横幅不是随包交付的业务 UI。首个 Vue 3.4 项目希望启用平台默认提示，并能调整位置、文案和视觉；React 消费者也需要同等选择。

## 决定

- 应用仍决定是否展示提示：根入口的 `usePwa()`、Provider 与 facade 不自动渲染 UI。两个框架包各增 `./ui` 子路径，业务显式挂载 `PwaUpdateNotice` 才启用。
- UI 只调用既有 `applyUpdate()`。用户先确认接管，接管后再显式点击刷新；`applyUpdate()` 本身继续不刷新。业务可替换 `reloadPage`，以接入未保存内容的保护逻辑。
- 默认非模态、右下角、中文、蓝灰色系；`position`、`messages`、常用色值的 `colors` 属性与 CSS 变量允许宿主定制。`colors` 只写到组件自身的 CSS 变量，优先于继承值；CSS 为显式导入的独立文件，根入口保持无样式副作用。
- “稍后”只改变当前组件可见性，30 分钟后重提醒；不会激活 worker，也不关闭更新检查。组件卸载清理自己的计时器。
- 等待状态持续 100 ms 后才显示卡片；恢复 worker 可能产生更短的 `updateWaiting` 真→假信号，组件忽略这种波动，不把它显示为“更新已完成”。稳定等待被另一个标签页接管时，仍提示当前页刷新。

## 影响

本 ADR 只扩展框架包的可选公开子路径，不修改既有入口和 worker 协议。原 `vue-react-adapters` 规格中的“无任何界面”约束继续适用于原有根入口；可选 UI 的验收归 [update-notice-ui](../../spec/update-notice-ui.md)。发布前须在真实浏览器验证布局、可访问性与多标签页；`0.1.0-beta.1` 不含此入口。
