# ADR-0050: 显式可移植部署与逐源发布门禁

## 状态

已接受（2026-10-01；本任务的项目所有者需求明确授权设计与实施）。

## 背景

现有 `PwaIdentity.origin` 在构建时必须固定，计划 v1–v3 和共享登记表 v1 都记录它。同一份构建产物部署到未知 HTTPS 域名时，填占位源既不能表示真实身份，也会使发布门禁误用其他域名的证据。

## 决定

- Vite 与 `buildPwaArtifacts` 仅在显式 `deployment: { kind: "portable" }` 时接受不带 `origin` 的身份。未写 `deployment` 与 `{ kind: "fixed" }` 等价，继续要求原有的完整固定身份。
- 可移植计划使用 schema/plan v4，保留策略版本 v3。v1–v3 仍只接受固定身份；不修改旧计划序列化语义。共享登记表 v2 去掉 `origin`，仅用于 v4；登记表 v1 仍用于固定计划。缓存名称只由 appId、environment 和种子决定，浏览器存储天然按同源隔离。
- 所有平台生成的浏览器 URL 均为同源绝对路径。可移植模式拒绝 Vite 的完整 URL `base`、完整 URL manifest 链接及平台输入中的外源 URL。对宿主业务代码或其他插件自行生成的绝对 URL 不宣称静态证明；上线前由宿主审查与浏览器证据覆盖。
- 发布系统按 `appId`、**实际 HTTPS origin**、environment、slot 维护互斥发布线与基线。可移植发布输入包含目标 origin 和在该源取得的逐路径最终响应 URL、HTTP 状态码及响应头证据；平台验证所有必需路径的最终 URL 的 origin、路径及 200 状态。仅传一个目标字符串不满足门禁覆盖。
- 共享根 `/` 与子 `/m/` 在登记表 v2 保持排除规则；发布顺序以同一实际 origin 的线上根计划证据比较。根计划来自其他 origin 时失败。
- 本仓库不访问生产网络、不保存凭据、不部署。外部编排器负责证据真实性、历史完整性、首次发布审批、保留资产与事故处理。

## 迁移

旧配置无需改动；不提供从固定身份自动升级的路径。想复用产物的宿主应显式改为 portable，重新评审身份、登记表和逐域名发布基线。同一域名上从固定身份迁入可移植计划需要人工身份迁移审批；既有安装状态不得被当作新模式自动继承。
