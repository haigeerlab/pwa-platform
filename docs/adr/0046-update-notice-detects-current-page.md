# ADR-0046：默认更新提示内置"页面已是新代码"判定

## 状态

已接受（2026-09-29，项目所有者裁决 [稳定版资格验证](../../tasks/stable-release-qualification/verification.md) 中记录的待裁决发现，选择"默认开启的内置判定"与"可选文案键"）。扩展 [ADR-0039](0039-optional-update-notice-ui.md) 的可选 `./ui` 子路径，不改根入口、事件或 worker 协议。

## 背景

应用壳导航在线时走网络优先。页面可能已经从网络拿到新 HTML 与入口脚本，而新 worker 仍在等待槽中，例如 Android WebAPK 从离线页导航回 `/app/`、或用户在线手动刷新。ADR-0039 的默认提示此时仍显示"有可用更新"，接管后再要求"刷新页面"。两句都与事实不符：页面已运行新代码，只差接管后的离线可用。"已是新代码"的判定此前只存在于[自绘更新提示](../../website/guide/update-prompt-custom.md)参考实现与公开示例中。

## 决定

- Vue、React 的 `PwaUpdateNotice` 在等待状态稳定（100 ms）后，每个等待周期发一次判定请求：`fetch(当前文档 URL 去掉 hash, { cache: "no-store" })`，比较响应中第一个 `script[type="module"][src]` 与本文档的同一元素。相同即"已是新代码"。
- 请求的是**当前文档 URL**，不是 `scope`：框架绑定不向 `./ui` 暴露配置，改为暴露会扩大根入口 API；而"重新加载当前页会不会换代码"正是要回答的问题。该请求是非导航 `fetch`，平台 worker 不以应用壳导航规则应答。
- 判定结果返回前不显示卡片。无入口模块脚本、请求失败、非 2xx、5 秒超时或周期结束中止，一律按"旧页面"处理，即此前的行为。
- 已是新代码：卡片使用 `currentTitle`/`currentBody` 文案，按钮仍是"更新"/"稍后"。确认后（或其他标签页完成接管后）卡片直接消失，不再出现"刷新页面"。接管仍须用户确认；worker 不自行 `skipWaiting`/`claim`，页面不自动刷新。
- `PwaUpdateNoticeMessages` 新增**可选**键 `currentTitle`、`currentBody`，内置 `zh-CN`、`en` 文案。宿主没有提供这两个键但覆盖了 `readyTitle`/`readyBody` 时，沿用宿主的 `ready*` 覆盖，避免完整自定义翻译里混入内置语言。
- 两包各自保留一份判定实现，与既有状态机的一致性做法相同。

## 影响

- 默认行为变化：挂载提示的页面在每个更新周期多一次同源 GET（带同源凭据，不写缓存）；卡片最晚推迟 5 秒出现。不挂载组件的应用不受影响。
- 适用前提与自绘参考实现相同：入口脚本地址随内容变化（Vite 默认带内容指纹）。入口地址不变的应用会被判为"已是新代码"而少一次刷新提示；这类应用应自绘提示并使用自己的版本标识。
- 当前 URL 在服务器上不存在（深链接 404）时退回"旧页面"行为。
- 验收见 [update-notice-ui](../../spec/update-notice-ui.md) "增补：页面已是新代码"。
