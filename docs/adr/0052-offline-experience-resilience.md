# ADR-0052：弱网导航宽限与有界离线恢复

## 状态

已接受（2026-10-05，项目所有者在方案及排期预览后要求继续），服务 [offline-experience-resilience](../../spec/offline-experience-resilience.md)。本地实现与 Chrome 受控边界、候选消费验收已完成；发布矩阵和线上验收未完成，见模块 verification。以增补方式修订 [ADR-0038](0038-network-timeout.md) 的导航失败处理和 [ADR-0036](0036-platform-default-offline-page.md) 的默认提示及自动恢复；保留两份 ADR 的历史。

## 背景

[优化前受控 Chrome 证据](../review/2026-10-05/offline-experience-boundaries.md) 表明：不足一秒的连接失败会立即显示离线页；六秒文档在五秒阈值下被称为断网；业务文档不可用而 worker HEAD 成功时约每十秒重载。增加超时只能改善一部分慢响应，不能阻止恢复循环。

## 决策

### 1. 导航重试显式开启，共享原有总预算

在当前策略版本和对应计划中添加可选 `navigationRetry: { delayMilliseconds: number }`，不增加任意重试次数或逐路由配置。字段缺省时旧导航行为及注入配置不变。

- `delayMilliseconds` 为 100–3,000 的整数，必须同时显式配置 `networkTimeoutSeconds`，且延迟小于该总预算。PRE 候选配置为 1,000 ms 宽限、5 秒总预算；这不会使六秒文档在五秒配置下成功。宿主另行评估是否采用十秒预算。
- 仅适用于原路由判断为 `navigate` 的同源文档 GET。最多增加一次串行请求，只有第一次读取明确失败且预算尚未耗尽才等待宽限重试。挂起请求、HTTP 4xx/5xx、API、图片和运行时缓存不加入重试。
- 总预算从首次请求开始计算，重试不能重新获得一份完整预算。截止时刻已到，不再发起新请求；截止回调与响应同刻竞争按事件实际处理先后决定，不承诺浏览器调度精度。
- 仍只约束取得响应头的等待；不承诺限制整份响应体或业务 loading。无可用回退时继续等待已经发出的网络请求；若网络已最终失败，按既有错误语义结束。预算耗尽后不再重试。
- 保留回退列表、请求 URL/查询参数、晚到结果收束和不写业务缓存的规则；运行时缓存的 Workbox 超时与晚到写入保持原语义。

### 2. 默认提示覆盖暂时不可达

默认中文标题和标题文字采用“暂时无法连接”，说明“网络连接或服务响应暂时异常，请稍后重试。”；英文同步采用暂时不可用的表述。保留手动重试、class、CSS 变量、自定义消息覆盖和无脚本可读性。不再保证“网络恢复后一定自动重新加载”。

### 3. 恢复探测原文档，结果只表示有限可达性

默认页通过带版本的 MessageChannel 请求控制它的平台 worker 探测当前文档。消息不接收任意目标 URL：worker 从真实 WindowClient 派生目标，校验客户端由该注册控制、同源、scope 内且非排除/拒绝路径；拒绝 worker 文件、离线文件、凭据 URL、非文档来源和非法消息。每客户端至多一个探测；worker 存活期间实施十秒最小间隔，页面侧也实施冷却，页面事件不能绕过它。worker 重启可丢失内存冷却，因此硬性重载预算保存在标签页中。

冷却到期按 worker 的单调时间 `performance.now()` 判断，清理定时器仅回收内存。清理回调延迟不应把已经到期的冷却继续视为失败；旧回调也不能清除同一客户端后续创建的新截止时间。2026-10-05 补测已用失败前置回归固化这两项边界；不改变十秒间隔或成功阈值。

- 请求闭合形态为 `{ type: "pwa:offline:probe", version: 1 }`，必须只有一个 MessagePort；回复闭合形态为 `{ type: "pwa:offline:probe-result", version: 1, reachable: boolean }`。遵守既有消息校验方式，不读取访问器，不信任页面提供的目标、状态或次数。客户端身份从浏览器源对象取得，受控归属用该注册的受控 clients 验证。
- worker 自身发起 GET，使用 `cache: "no-store"`、同源模式与凭据、`redirect: "error"` 和 `Accept: text/html`；不调用缓存引擎或导航回退，不写入缓存。原 URL 的查询参数用于网络请求，片段丢弃；消息回复仅为成功/失败，不返回或记录 URL、响应正文与敏感参数。
- 三秒预算覆盖响应头和非空首个正文块；接受 200、HTML 类型、同源且未重定向的响应，之后取消读取并释放请求。错误、空正文、挂起、跳转和不合类型均失败。响应内容不解析、不持久化。
- 此探测证明文档读取路径可达，不能证明全部业务 API、整个响应体、JavaScript 或页面渲染可用。源站/CDN 返回 200 的业务错误页仍可能通过，所以恢复重载必须另有硬性上限。
- worker 内发起请求避免页面 fetch 再被本地缓存/兜底回答；`no-store` 约束浏览器 HTTP 缓存，不能被描述为绕过一切 CDN。依据 [Fetch Standard 的 fetch() 步骤](https://fetch.spec.whatwg.org/#fetch-method) 与 [cache mode 定义](https://fetch.spec.whatwg.org/#concept-request-cache-mode)。实现和浏览器测试仍须证明该路径不会被平台 worker 回退误判。
- 页面侧消息等待上限四秒，清理计时器与 MessagePort；worker 侧三秒网络超时后收束请求。旧 worker 不支持协议、无 controller、回复非法或消息超时：关闭本次自动恢复，保留手动操作；不得退回 HEAD worker 即成功的逻辑。合法 `reachable: false` 是一次可退避的探测失败，不关闭整个周期。

### 4. 两次连续成功，跨重载最多自动刷新一次

默认恢复规则固定，不新增宿主调参选项：

- 可见页首次检查不早于十秒；一次失败后等待十秒，连续失败按二十、四十、六十秒退避，之后保持六十秒。没有重叠探测。online/重新可见只能在允许时刻发起检查，不能直接重载。
- 两次相隔至少十秒的探测成功才可自动重载。隐藏期间取消成功序列，已发请求收束后不重载；再次可见重新验证。控制 worker 改变时丢弃旧结果。
- 使用 sessionStorage 保存“当前标签页、当前 worker 脚本路径”的预算；最多一次自动重载，必须先成功持久化预算，再刷新。键和值不包含业务路径、查询参数或响应数据。跨默认页重载保留预算；只读探测成功、时间经过、页面恢复、控制器升级均不自动清零。
- 存储读取失败、状态非法、写入失败或无法验证写入，均关闭自动重载；不退化成内存预算。耗尽后停止探测与自动重载，保留按钮。
- 用户主动点击重试可明确开启新周期并重载一次；快速连续点击以页面内锁合并。即使存储不可用也允许手动重载，但自动恢复继续关闭。新标签页具有独立预算。
- 选择这种保守预算意味着：一次自动恢复成功后，该标签页以后再次无法连接时，需要用户点重试，才重新获得一次自动机会。当前迭代不引入业务页成功确认协议，以免探测成功后又落入兜底而错误重置预算。

### 5. 升级边界

升级受影响的现有包、重新构建并部署后，新的默认离线页才具备修正；新导航重试还须宿主显式开启。业务自带离线页不被覆盖，应自行对齐有界恢复。新旧 worker/页面混用时默认手动降级。内联脚本变化必须同步 CSP hash，不能要求关闭 CSP。

本轮不改变身份、scope、缓存命名空间、更新确认接管协议，也不新增业务资源缓存。

## 影响

- 增加 contracts、core 到现有 sw-runtime/vite 修改闭包；消息实现归 sw-runtime，默认页消费，不向 client-runtime 增加业务页事件或刷新行为。
- 重试仅增加一次适用文档请求；恢复探测是有界的文档 GET，须在宿主验收记录其请求行为。
- 三秒探测预算比宿主五/十秒导航预算更保守：持续较慢的网络可能无法自动恢复，而手动导航仍可成功。默认提示不承诺自动恢复，验收必须记录这个差别；不能把恢复探测失败称为设备断网。
- 保守预算减少全自动恢复次数，但能保证失败循环不会无限打断用户。
- 验收须覆盖旧配置产物、请求次数、五/十秒总预算、两次成功、隐藏/online、跨重载及存储故障、严格 CSP、旧 worker 升级与候选包消费。模拟连接关闭不等同真实丢包测试。

## 拒绝的方案

- 仅将五秒改成十秒：不能修复立即失败或恢复循环。
- 所有失败立即离线、或设备显示联网就永久等待：分别损害短暂故障与长时间不可达体验。
- HEAD worker 成功就自动刷新：没有验证原文档读取。
- 页面内一次计数、短 TTL 自动重置：再次进入兜底时重新获得预算，循环仍可发生。
- 默认重试所有请求、缓存业务页面或增加业务成功确认 SDK：扩大本次范围与兼容成本。
