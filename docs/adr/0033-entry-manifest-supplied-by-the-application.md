# ADR-0033：入口清单由业务应用提供，平台不再验签

## 状态

已接受（2026-09-23，项目所有者）。取代 [ADR-0017](0017-entry-manifest-trust-model.md) 的信任模型；[ADR-0018](0018-entry-resilience-delivery-boundary.md) 的交付边界相应修订。服务 [pwa-entry-resilience](../../spec/pwa-entry-resilience.md)。

## 背景

ADR-0017 把信任根放在构建期的公钥集与种子清单上：入口清单必须由离线私钥签名，验签通过才可用，且入口 Origin 必须在构建期批准的列表内。这套模型假定清单从**不可信的传输通道**（独立 Origin 上的发现源）取得，因此可信度不能来自"它从哪里下载"。

首个业务接入方评审后提出三点，2026-09-23 经项目所有者确认：

- **清单应当由应用自己的后端提供，而不是独立 Origin 上的静态文件。** 后端接口可以在后台配置，运维随时改；用户在线访问时取一次存下来，域名失效时用存下来的那份。外部静态文件虽然内容也能改，但多一个外部依赖与 CORS 配置，没有换来相应的收益。
- **数据来自应用自己的 Origin 时，签名挡不住真实攻击。** 能控制该 Origin 的攻击者本就能直接改写前端代码，签名只是多一道对他无效的门。
- **业务方已有的接口加密不能替代签名，但也不需要替代。** 对称密钥必须打进前端包，任何人都能取出并伪造密文；它提供的是机密性，不是真实性。在同源前提下，真实性由"谁能控制这台服务器"决定。

同时，构建期的 Origin 批准列表与这个场景直接冲突：域名被封后临时启用的新域名不可能出现在几个月前的构建里，于是白名单挡住的是发布方自己。

## 决策

- **平台不再验签，也不再持有信任根。** 删除公钥集配置、构建期种子清单、私钥形态扫描与发现源请求。`@pwa-platform/entry-resilience` 不再包含任何密码学校验。

- **清单由应用交入。** 应用用自己的请求层取数（鉴权、加解密、重试、轮询节奏都归应用），解密为明文对象后调用 `updateEntryManifest(data)`。平台不发起这次请求，也不接收解密函数：把 token、拦截器、业务错误码塞进一个回调里，不如让应用取完再交进来。

- **平台负责保存、判新旧、校验形状与展示。** IndexedDB 保留最后一份清单，`sequence` 更大才覆盖；过期不展示；`origin` 必须 HTTPS（本地回环例外）、`startPath` 不得含 `..` 或反斜杠、`entries` 至多 5 条。这些校验防的是发布方自己的 bug，不再声称防外部攻击者。

- **取消 Origin 批准列表。** 清单中的入口不再与构建期的白名单比对。

- **用户确认这一层不变。** 平台绝不自动导航；入口只在恢复页上展示，由用户亲自点击后才跳转，返回路径仍逐条校验。这是删除签名后仍然保留的唯一防线。

- **安全边界写入规格。** 采用本模型后，**谁能控制应用后端，谁就能把全体已安装用户引向任意域名**。这在同源前提下与"谁能改前端代码"等价，因此可接受；接入方必须知道这条边界，并把该接口按写操作级别保护。

## 备选方案

- **保留签名，业务方自建密钥管理。** 不采用：接入方需要建立离线签发、公钥核对与台账制度，成本高于收益；同源前提下它挡不住真实攻击。
- **业务方提供解密函数，平台仍发请求。** 不采用：鉴权、拦截器、业务错误码难以塞进一个回调，等价于把应用的请求层重写一遍。
- **保留 Origin 批准列表。** 不采用：域名被封后临时启用的新域名无法事先登记，白名单只会在真出事那天挡住发布方自己。
- **同源免签、外部源仍验签的双模式。** 不采用：两套规则会让规格与实现复杂一倍，而外部源在本次接入中没有需求。将来若确有第三方托管的发现源，再以新的 ADR 引入。

## 影响

- `@pwa-platform/entry-resilience` 的公开面变为 `updateEntryManifest` 与 `checkEntryRecovery`；构建插件只保留 `identity` 与可选的 `maxValidityDays`。
- 接入成本从"建立一套密钥管理制度"降为"提供一个接口与一次调用"。
- [入口恢复演练](../operations/entry-recovery-drill.md)中的离线签发、密钥轮换、撤回与台账不再适用，需重写；[发布与事故处置手册](../operations/release-and-incident-runbook.md)的"入口清单签发、密钥轮换与撤回"一节随之作废。
- 已有的验签实现与测试随本次修订删除；`verifyEnvelope` 等导出不再保留，以免被误认为仍在生效。
- 本包尚未发布到 npm（`private`，`0.0.0`），没有外部调用方，因此直接替换公开面，不提供兼容层。
