# ADR-0036：平台提供可选的默认离线页

## 状态

已接受（2026-09-24，项目所有者）。服务 [vite-adapter 的"修订：平台默认离线页"](../../spec/vite-adapter.md)。补充 [ADR-0013](0013-client-facade-and-page-side-lifecycle-events.md) 中"界面归应用"的适用范围，与 [ADR-0018](0018-entry-resilience-delivery-boundary.md) 中恢复页由平台发布的做法保持一致。不修订任何既有结论。

## 背景

离线导航回退（`policy.offlineFallback`）开启后，平台 worker 在断网时返回预缓存的离线页，但页面本身必须由业务写好放进 `public/`，平台不提供模板。2026-09-24 的平台完成度审查发现，示例中的离线页只有一行英文，每个业务都要各自手写页面、样式与暗色模式，而离线页的内容在各业务之间几乎相同。

平台此前自己渲染的界面只有入口恢复页（ADR-0018）。更新提示、安装引导、推送权限都遵循 ADR-0013：平台只给状态与方法，界面由应用实现。

## 决策

- **Vite 插件新增可选的 `offlinePage` 选项**，开启后在 `offlineFallback.path` 位置生成默认离线页。只有 `offlineFallback` 已开启时才能使用；该位置已有业务文件时构建失败。不改 `PwaPolicy`、`PwaPlan` 与 worker 配置。
- **页面在计划编译之前加入产物**，与业务自带的离线页走同一条路径：进入预缓存，经过既有的离线页存在性校验与产物校验。
- **语言在构建期固定**：内置 `zh-CN` 与 `en`，可用 `messages` 覆盖文案。文案经 HTML 转义写入静态 HTML，页面不依赖脚本就能完整显示；唯一的内联脚本是固定文本，负责重试与联网后自动重载。
- **样式沿用入口恢复页的契约形态**：一段内联默认样式、`--pwa-offline-*` 变量、亮暗两套、宿主 `css` 追加；三段内联内容的 CSP 哈希在构建时输出，不写文件。class 与变量一经发布即为公开契约。
- **与入口恢复页对齐命名与做法，但不共享代码**：两个包之间不为一段样式新增依赖。

### 与 ADR-0013 的关系

ADR-0013 的"界面归应用"针对的是**应用正在运行时**的交互：更新提示、安装引导、推送权限都嵌在应用自己的页面里，外观与时机应由应用决定。离线页与入口恢复页属于另一类：它们出现在**应用无法运行时**，此时应用的代码与样式都不可用，平台是唯一能提供页面的一方。因此这两类页面由平台提供默认实现，应用可以换肤、改文案，也可以不用平台的实现而自带页面。更新、安装、推送的提示仍然只归应用，本 ADR 不改变这一点。

## 影响

- 未设置 `offlinePage` 时，插件产物与此前逐字节相同。
- 平台多出一组需要长期维护的公开契约：选项形态、诊断码、class 与变量名、两种内置语言的文案。
- 严格 CSP 的站点需要把构建时输出的哈希加入响应头，否则重试脚本被拦截；页面内容仍然可读。
- Nuxt 适配器暂不暴露该选项，Nuxt 应用仍需自带离线页。

## 拒绝的方案

- **在 `PwaPolicy` 中声明默认离线页**：离线页是构建产物，不是请求判断的意图；放进策略需要升 schema 版本，并让 core 承担渲染职责。
- **开启 `offlineFallback` 但未提供文件时自动生成**：会取消现有"缺文件即构建失败"的保护，业务漏放文件时不再被提醒，而是静默得到平台页面。
- **运行时按浏览器语言切换**：需要额外的脚本与语言检测，而业务的用户群体通常是确定的；以后需要时可以在不破坏现有选项的前提下加上。
- **引入 CSS 工具库**（Tailwind、UnoCSS 等）：页面只有几个元素，默认样式是一段固定文本；工具库会增加构建链路，也会让 CSP 哈希随生成结果变化。
