## 核心结论

1. **整体成熟度高于对标项目。** 默认拒绝缓存、身份契约、两层恢复（恢复 worker 加入口恢复页）、构建期校验，这几项在 8 个对标对象中都没有同等的实现。本次实测：lint、typecheck、build、文档站构建全部通过；单元测试 2388 个用例、Chrome E2E 232 个用例全部通过。
2. **没有 P0 或 P1 风险。** 最值得优先修的 3 项，都能在半天内完成：
   - 导航请求没检查 `Authorization`，与规格不一致（R1）；
   - 身份契约没有检查“scope 不能超出 SW 脚本所在目录”（R3）；
   - 缓存准入拒绝时没有任何诊断输出（R8）。
3. **只看文档接入能一次成功**，但有一个高严重度陷阱：`vite preview` 默认给响应加 `Vary: Origin`，public-read 缓存会静默失效。此外文档漏写了 4 处默认行为：单页应用深层路由断网时的表现、4xx/5xx 不显示离线页、多标签页、断网恢复。
4. **证据的最大短板是浏览器覆盖面。** 所有 L3 都只在 Chrome 桌面上跑；手机证据（L4）真实存在，但集中在 2026-09-26 至 27 这两天、一台 Android 和一台 iPhone 上，还留有 iPhone 断网恢复后“未注册”的问题（R9，ADR-0041 定为阻止 iPhone 晋级生产通道的条件）。审查期间合入的 PR #25 补齐了 iPhone 安装窗口内更新、Safari 双标签页协调，R10 随之解决，相关文档已于 2026-09-28 更正。
5. **“名称不等于语义”的地方**：
   - `cache-first` 只是“加入预缓存”的标记，不是运行时策略；
   - “恢复页”和“恢复 worker”在代码上没有交集；
   - 离线页不是服务器故障页；
   - 平台从不 `clients.claim`，所以首次打开的页面不受 SW 控制。
   这些在产物 2 和 5 中都逐条写明了。

## 2026-09-28 进展

审查提出的 19 条建议和 15 项风险已按三批处理，共 16 个 PR（[#27](https://github.com/haigeerlab/pwa-platform/pull/27)–[#42](https://github.com/haigeerlab/pwa-platform/pull/42)），全部合入 `main`；合并后 `main` 上的 CI 全部通过。这些改动已于 2026-09-28 随 npm `0.2.0` 发布（[发布记录](../../../tasks/package-distribution/release-0.2.0.md)）。

| | 数量 | 说明 |
|---|---|---|
| 建议已完成 | 17 / 19 | #5 因 worker 读不到 `Set-Cookie` 而撤回；#10 部分完成（真机补测）；#18 评估后不采用 |
| 风险已修复、缓解或查明 | 11 / 15 | 另有 R2、R13 以文档登记；R9（iPhone `not registered`）、R11（纵深防御）未处理 |
| 修复中新发现并已解决的问题 | 6 | UI 与联网测试套件不在门禁、macOS 专有截图路径、叠加 PR 未进 `main`、冒烟测试依赖本机 store、CI 每次合并都要整轮重跑、台账推送一行误记 |

几处改变了审查原结论的事实：

- **R1 比审查时判断的更容易触发**：新增的 Chrome E2E 证明带 `Authorization` 的导航确实会被写入缓存，原先“SW 看不到这个头”的降级理由不成立。
- **R2 的原建议无法实现**：Fetch 规范不让 worker 读取 `Set-Cookie`。
- **R4 被高估**：ADR-0025 和发布协议早已规定必需检查集，只补了一个 `requiredReleaseChecks(plan)` 辅助函数。
- **审查期间合入的 PR #25** 补齐了 iPhone 安装窗口内的更新和双标签页证据；按 ADR-0041，R10 已解决。

每条风险和建议的当前状态见 [06 风险清单](06-architecture-risks.md) 与 [07 改进建议](07-recommendations.md) 开头的“2026-09-28 状态”一节；证据等级的变化见[功能证据台账](../../operations/feature-evidence-ledger.md)。

仍然开放的事项：R9 根因（需要 iPhone 真机）、Android N-1 与单源真实故障证据。
