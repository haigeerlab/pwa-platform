# 验证记录：release-orchestration-protocol

## 范围

本模块只交付外部发布系统与 PWA 平台之间的文档协议、门禁接线和发布记录模板。它没有新增
部署代码、网络客户端、凭据、数据库或 CI 配置。平台包仍只接受调用方采集的事实，边界见
[ADR-0025](../../docs/adr/0025-release-gate-completeness-and-external-orchestration.md)。

## 静态核验

- 协议、运行手册、身份基线规则和模板的相对链接、目标文件、关键中文锚点及 Markdown 表格
  已核对；`git diff --check` 通过。
- Spec Guard 产物核验通过（2 通过、0 失败；仅报告不会读取的遗留 tracker 状态）。
- 协议明确普通发布必须合取 `verifyRelease` 的 `report.ok` 与覆盖结果的 `ok`；首次发布和身份
  迁移保留原始 `baseline-missing` 或 `baseline-mismatch`，并要求批准引用，不能省略检查。
- 身份迁移会同时锁住旧身份键、候选身份键和稳定槽位锁，避免只锁候选键而与旧发布线并发。

## 纸面状态机核对

| 情形 | 核对结果 |
|---|---|
| 普通独立源发布 | 四项机器检查覆盖且报告通过，加上 CI、浏览器、安装、恢复演练和类生产证据后进入 `verified`；生产成功后才进入 `recorded` 并写基线/历史。 |
| 首次生产发布 | 显式 `baseline` 查找得到 `verify.baseline-missing`；覆盖完整、其他门禁通过且平台负责人批准后才可作为例外进入 `verified`，不能把诊断改写为通过。 |
| 同源子应用发布 | 必需集额外包含 `release-order`，并保存实际线上根计划；缺根计划或检查失败均不能进入 `verified`。 |
| 失败发布 | 缺失事实、覆盖不完整、审批缺失、部署失败或记录写入失败均保持非成功状态；旧基线与成功历史不变。 |

## 本地模块质量门禁（2026-09-19）

- 相对 `main` 审查协议、模板、运行手册接线、身份基线规则与验证记录的正确性、可读性、架构边界、安全性和运行时影响后无遗留阻断项；未新增包、依赖、网络调用、凭据或运行时代码。
- 审查曾发现状态图把 `aborted` 错画为流向 `failed`，且 `prepared` 的“事实已采集”定义与步骤顺序冲突。已改为两个独立终态，并要求采齐事实后才写入 `prepared`，使模板、状态表与执行步骤一致。
- 文档静态门禁重跑：相对链接、关键锚点、Markdown 表格、基线唯一 `target` 条目与 `git diff --check` 均通过。分支未改代码；其基点 `main` 已在 release-gate-contract 质量门禁中完成全工作区 lint、构建、测试与类型检查，故不重复执行无新增信息的代码门禁。

## 未取得的证据与状态

- GitHub 当前不可用；未取得远端 CI 实跑证据。
- 外部发布系统、生产部署凭据、真实发布历史和生产演练不在本仓库范围，尚未取得相应证据。
- Spec Guard 的 `documentation_impact` 与 `documentation_verification` 仍无法解析项目既有中文基线：其当前解析器要求英文表头与每个模块的影响表。为避免扩大为全仓基线迁移，本模块如实记录该工具限制，不宣称其通过。
- 因此文档基线中的 `release-orchestration-protocol` 保持 `target`；本记录只证明协议和模板的本地静态、纸面核对。
