- 不为本轮规划创建远端 Issue、推送、发布 NPM 或部署宿主。需要事项追踪时先核实已选账本，不假定 Git remote 就是事项后端。

## OE1：冻结技术决策和兼容契约

推荐方案见 [ADR-0052](../../docs/adr/0052-offline-experience-resilience.md)：导航显式开启一次重试，1 秒测试宽限共享 5 秒总预算；默认页用 worker 派生的原文档网络探测，连续两次成功才尝试恢复；每标签页/worker 路径自动刷新最多一次，预算跨重载保存，仅用户主动重试开启新周期。旧 worker、预算存储或协议不可用时保留手动恢复。方案已接受，实现遵守该契约；实际发布和宿主部署另行验收。

1. 核对导航重试与 `networkTimeoutSeconds` 的关系，选择显式启用的导航专用策略或有明确升级语义的兼容修正；不扩展运行时缓存的处理。
2. 冻结首次等待、失败宽限、最大请求数和总预算；明确阈值竞争、无回退及响应体等待的范围。
3. 冻结探测原文档或同源只读入口的方式，证明结果来自网络，不经过缓存或离线兜底。不以 HEAD worker 可达代替业务可用。
4. 冻结成功阈值、超时、退避、冷却、自动重载预算、跨重载保存、重置判据及状态不可用时的手动降级。
5. 记录新 ADR 并增补 ADR-0038、0036；涉及公开协议时对齐 ADR-0013、contracts/core/client-runtime 和能力图依赖。

**验证：** 每个公开字段有类型、非法值与兼容断言；每个状态迁移有停止条件；规格矩阵中数值剖面均能映射至确定的实现配置。未解决决策不转入 OE2 实现。

## OE2：固定回归夹具，先复现三个缺陷

1. 复用 browser-test-harness 的服务器能力，提供文档延迟、短暂连接关闭、持续失败、探测独立延迟/状态及请求时间记录。
2. 将“900 ms 窗口内连接失败后恢复”“worker 正常但文档持续失败”“探测成功但重载文档失败”固化为回归测试。
3. 浏览器内部网络重试与平台重试分别记录；至少用导航计数观察 60 秒的循环，避免只看截图或最终页面。
4. 确认真实 worker 控制和已准备的兜底；用隔离 origin，测试结束清理服务器与上下文。

**验证：** 优化前基线确实违反目标断言；普通联网、4 秒响应和真断网对照能区分故障注入与夹具错误。回归失败作为实现起点，不把优化前失败计为修复通过。

## OE3：导航失败宽限和预算

修改 `packages/sw-runtime/src/worker/handlers.ts` 及 OE1 必须调整的契约、编译、注入位置。

- 串行、有界重试适用的导航文档；挂起请求不并发重试。
- 保留及时 HTTP 响应、无回退可达性、排除路径、查询参数、晚到结果收束与不写业务缓存。
- 新策略不启用的兼容路径按 ADR 验证；与 network-first 运行时缓存隔离。

**验证：** worker fake-clock 用例覆盖 OE-A1–A8；契约变更有正反例与编译产物检查；至少运行一次带真实 worker 的短暂故障浏览器回归。

## OE4：默认提示和有界恢复

修改 `packages/vite/src/offline-page.ts` 及经 OE1 确认的恢复协议实现。

- 默认中英文提示不误称设备离线；自定义消息和样式契约保持兼容。
- 真实业务可用性探测、有界成功判定、单请求并发、退避与冷却。
- 预算跨重载有效，耗尽停止自动重载；无法保存状态时手动降级。
- online 事件、可见性与快速点击均不能绕过限制；保留用户主动重试。
- 生成的内联脚本和 CSP hash 同步；业务自带离线页不被覆盖。

**验证：** 离线页单元/生成测试、CSP 浏览器测试及 OE-R1–R6。尤其证明 worker HEAD 200、业务失败时 60 秒内不自动重载，以及测试预算 1 次时最多重载 1 次。

## OE5：兼容和浏览器验收

- 覆盖旧配置、根/子路径、查询参数、排除路由、缺兜底、首次未受控制、业务页面 API/图片异常。
- 验证既有缓存安全拒绝、更新等待/确认接管以及无脚本提示。
- 按既有浏览器矩阵运行桌面和移动端可用环境；请求数、重载数、时间和失败/跳过均写入 verification。
- 真实丢包、现场宿主和独立安装窗口的验证与服务器故障模拟分列，不互相替代。

**验证：** OE-C1/C2 及所有核心回归通过；环境缺失保留未验证项，不降低门禁或删除反向用例。

## OE6：包消费和升级交接

- 确定受影响 NPM 依赖闭包和版本语义，构建并打包候选 tarball。
- 从候选 tarball 在隔离 Vite 宿主安装、构建，验证生成 worker、默认提示、CSP、短暂故障和恢复次数限制。
- 演练旧 worker 接管到新构建；写明需升级包、宿主配置是否变化、重新构建/部署及自带离线页要求。
- 记录回滚是否能够恢复旧产物与配置；不以提高超时、关闭 CSP 或启用业务缓存作为修复捷径。

**验证：** OE-P1 通过，源代码与打包内容一致，未发布版本不写成 NPM 已上线；宿主上线验收另有记录。

## OE7：审查、门禁与交付

- 自审导航准入、无并发重试、计时器清理、响应收束、预算隔离、状态失败降级、探测跳转、CSP 与兼容差异。
- 先运行受影响包的定向测试/typecheck/build，再运行项目要求的全仓 lint/typecheck/test/build/browser 门禁。环境无法运行时记录命令与诊断，不自动安装或声称通过。
- 文档更新对应事实源、接入说明与发布候选记录；验证结果明确“已实现”“已验证”“待发布”“待宿主验收”。

**验证：** 已审范围与最终差异一致；无核心缺陷遗漏。PR、NPM 发布及部署只在其实际授权与前置门禁满足时继续。

## 首个实现切片与停止条件

满足排期及 OE1 后，首个切片为 OE2 的短暂失败回归：已有 worker 控制时，服务端故障窗口 900 ms，恢复后应在配置宽限内取得文档且不整页兜底。首先证明优化前失败，再修改 OE3 使其通过。

以下情况停止相关切片并保留证据：无法证明探测来自真实网络、需要改变身份/缓存安全边界、跨重载预算可能被绕过、旧策略兼容方案未明确、关键浏览器验收失败或环境证据未知。不能通过扩大等待到无限、删除测试或降低目标来收口。
