# 弱网体验候选升级说明

2026-10-05 本地开发候选，尚未发布或部署到 PRE。最新临时打包版本为 `0.4.0-next.20261005.2`，包含后续探测冷却到期修复；第一批 `.1` 保留为历史证据。正式版本与通道在发布前确定，不能直接把下列候选号当作 npm 上已有版本。

## 宿主需要修改什么

| 位置 | 修改 | 生效条件 |
| --- | --- | --- |
| 平台依赖 | 升级现有 `@pwa-platform/vite` 与宿主显式依赖的 contracts/client-runtime/框架包到同批正式版本，更新锁文件 | contracts、core、sw-runtime、vite 为直接修改包；其余公开包按现有十包同版本分发约定交付 |
| PwaPolicy | 在现有 `networkTimeoutSeconds: 5` 旁添加 `navigationRetry: { delayMilliseconds: 1000 }` | 显式启用一次串行导航重试；缺省保留旧导航行为 |
| 默认离线页 | 继续使用 `offlinePage: {}` 或既有 locale/messages/css | 重新构建后获得新提示与有界恢复；覆盖过的文案需人工核对，不会被平台强行替换 |
| 自带离线页 | 自行对齐中性提示、真实入口探测、跨重载预算及手动出口 | 平台不会覆盖业务自带 HTML；仅升级包不能修复其恢复脚本 |
| CSP | 使用新构建日志中的样式和脚本哈希，确认 worker CSP 允许同源连接 | 不能复用旧脚本哈希或关闭 CSP 作为修复 |
| 发布产物 | 重新构建，整体部署 HTML、worker、离线页及资源 | 保留当前身份、scope、worker URL、缓存命名种子与更新确认流程 |

```ts
// 写在现有 POLICY 中，与 resources 同级
networkTimeoutSeconds: 5,
navigationRetry: { delayMilliseconds: 1000 },
```

延迟必须为 100–3,000 的整数且小于总预算。五秒内仍未取得响应头就按既有规则兜底；六秒文档不会因为加了重试而变成成功。若实际业务需要十秒等待，应单独评估和验收 `networkTimeoutSeconds: 10`，不能承诺“设备联网就不进入提示页”。运行时缓存、业务 API 和图片不加入这项重试。

## 用户能观察到什么

- 短暂文档连接失败会等待宽限，再尝试一次；挂起请求不并发重试，HTTP 4xx/5xx 原样返回。
- 默认提示为“暂时无法连接”，不会把所有超时都称作断网。
- 默认页首次至少等待十秒，原文档连续两次探测成功才尝试自动刷新；失败按十至六十秒退避。
- 同一标签页、同一 worker 路径最多自动刷新一次，预算跨重载保存。仅点击“重试”开启新周期；一次恢复成功后以后再次故障也可能需要手动操作。
- 旧 worker、新旧页面混用、存储不可用或协议回复不可信时保留手动恢复。三秒探测可能拒绝较慢连接，但手动导航仍可在五／十秒预算内成功。
- 探测只证明文档入口可达，不能证明业务 API、脚本和页面渲染全部正常；请求使用浏览器 HTTP `no-store`，不能表述为绕过一切 CDN。

## 发布验收与回滚

本地候选已从十个 tarball 离线安装并构建。已验证由 Git 基线重建的旧 worker 经用户确认接管到新 worker，以及短暂失败和两个 60 秒恢复边界，见 [验证记录](verification.md)。线上 PRE 仍不能据此声明已升级。

发布前仍需正式 CI、选定发布通道的 N/N-1 和原生安装/恢复证据；实体手机、真实丢包、DNS/证书异常与安装窗口本轮未验证。随后宿主部署再验证主要 PC 导航路由、离线兜底准备、更新提示、CSP 和恢复次数。

不启用重试可删除 `navigationRetry` 后重建；这不会关闭新默认页的恢复规则。需要暂时关闭自动恢复时，使用保留中性提示与手动按钮的宿主离线页，并关闭生成选项后重建，避免路径冲突。
完整回滚须发布经过核验的旧版本产物并按既有更新流程接管。恢复旧默认页也会恢复其 HEAD 判断及循环风险；本轮未演练事故回滚，不把历史产物存在视为回滚通过。
