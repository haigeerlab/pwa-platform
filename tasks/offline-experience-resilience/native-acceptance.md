## 依据与方法

- 平台代码固定于 `2863ef4a9206517929b5ad99ed2ae7726a15cf5b`，本地未发布候选 `0.4.0-next.20261005.2`；macOS 15.7.3。构建用干净检出的 workspace dist，与候选 tarball 字节一致，不是从 npm 注册表安装的正式版本。
- Vue／React 使用专用本机 origin、测试身份和独立浏览器配置。Chrome 154 新建未登录配置；Chrome 153 使用独立临时配置。未使用业务账号，未修改线上站点。
- 所有安装、图标启动、按钮和刷新操作均经原生 UI。Chrome 153 用 Playwright 只读观察实际安装事件、显示模式、可见性及导航事件，没有派发模拟安装事件或覆盖可见性。Vue 首次安装事件只保留工具观察记录，未声称存在单独保存的原始事件文件。
- 5 s 总预算、1 s 重试宽限；服务器制造延迟或连接失败。4 s 响应显示业务文档，6 s 响应显示“暂时无法连接”。这是服务端故障模拟，不是运营网络真实丢包测试。
- Chrome 153 的 Vue／React 持续文档失败分别观察约 80／81 s，无新增导航；探测成功而真实导航失败分别观察约 88／85 s，各新增一次自动导航，此后保留兜底和手动入口。网络恢复及手动重试均回到 v2 文档。
- Chrome 154 Vue 的持续文档失败，两个相隔约 83 s 的只读状态记录具有同一 `performance.timeOrigin`、预算 0、standalone true；React 的持续文档失败观察超过 65 s，服务端记录两次文档探测、零次导航请求。此外，两套 Chrome 154 原生窗口在先前恢复后再次导航失败，约 185 s 没有新增导航网络请求，随后手动重试成功。网络请求记录不是通用的文档重载计数器。
- 原生更新测试使用相同平台候选、同一身份与 worker URL 的应用 v1／v2 构建。v2 新增测试导航链接，两份 worker 哈希不同；观察等待提示和用户确认。没有把它表述为 npm 旧版本升级，亦未读取接管后 active worker 的二进制哈希。

## 保留的缺口

900 ms 短暂故障已在自动化及候选消费者中通过，但原生窗口未取得可靠的对应故障窗口证据。原生隐藏窗口尝试未满足实际 `visibility=hidden` 前提，不计通过。Chrome 154 React 的 standalone 数值和精确“一次自动重载”状态读数未完成：原生输入工具漏标点，随后 Chrome 防粘贴保护阻止粘贴；未绕过该保护。窗口选择错误的记录已剔除，工具等待和输入故障不计为产品响应时间或产品测试失败。

四个组合的上述基础流程不等于完整原生矩阵通过。真实丢包、其余移动／桌面环境、类生产恢复 worker 发布演练及 ADR-0031 签署仍按各自门禁补齐；本模块 OE5 保留未完成。恢复网络的检查不能代替 [恢复演练手册](../../docs/operations/recovery-drill.md)。

原始观察、服务器请求、构建脚本、四份构建、截图及哈希保存在仓库外的本地证据目录 `native-acceptance/`；浏览器配置与个人资料未归档。Chrome 153 测试上下文已关闭；本机测试应用与专用 Chrome 154 配置保留，便于补测。
