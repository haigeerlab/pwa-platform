## 过程与核验

1. 发布前确认 `npm whoami` 为 `jianian`、`npm org ls pwa-platform` 显示 owner、registry 为 npm 公共 registry；九个目标版本均不存在。
2. 从与项目改动文件逐一一致的临时副本，按依赖顺序逐包执行 `pnpm publish --access public --tag next --no-git-checks`。没有创建分支、提交、推送或 GitHub 对象。
3. 每包发布命令返回成功；公开 registry 的九个版本均可读取 `dist.integrity`。逐包下载公开 tarball 与本地候选比较：文件列表和每个文件内容一致。五包压缩文件逐字节一致；另四包仅打包时 `package.json` 的 JSON 键顺序不同，解析后内容一致。
4. 全新临时消费项目从公共 registry 安装全部九包及 Vite/Vue/React peer 依赖成功；九个包的主入口均可由 Node ESM 导入。
5. 每包当前同时显示 `next: 0.1.0-beta.0` 和 `latest: 0.1.0-beta.0`。首包带 `--tag next` 发布后自动产生 `latest`；两次使用 `npm dist-tag rm ... latest` 均收到 registry `E400`，未改变标签。项目所有者知悉并明确要求继续九包 beta 发布。`latest` 此时仍指向 beta；无版本限定的安装可能取得 beta，不能把它解释为稳定版。[npm registry 元数据说明](https://github.com/npm/registry/blob/main/docs/responses/package-metadata.md)指出每个包均有 `latest` 标签。

## 后续门禁

- 不再把“`latest` 未设置”列为首发预发布的验收断言；文档和升级说明必须明确 `latest` 当前也指向 beta。正式稳定版发布时再将 `latest` 指向完成生产验收的版本。
- 本次没有远端 CI、Android 与浏览器 N/N-1、真实安装提示、生产域名响应头、CDN 回滚或恢复演练证据。业务应用上线仍按原有发布门禁执行。
- 六个延后工作区包仍为私有；业务 API 运行时缓存、私密数据缓存、离线写入/自动重放和 Push 不属于此版承诺。
