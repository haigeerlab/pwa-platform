# 0.3.1 npm 发布计划

## 范围与成功标准

- 从合入 Windows 修复的 `main` 准备补丁版：十个公开 `@pwa-platform/*` 包统一为 `0.3.1`，npm `latest` 最终逐包指向该版本；私有包不发布。
- 修复范围限于 `@pwa-platform/vite`、`@pwa-platform/entry-resilience` 的 Windows Vite 路径处理，以及仓库发布脚本的 Windows pnpm 启动。公开 API 与 PWA 身份、scope、缓存行为不变。
- 记录候选提交、CI 和本地门禁、tarball 哈希、npm 提交与最终集中读回。文档站在 npm 发布前沿用已上线的 `0.3.0` 内容；包公开后再更新版本说明与安装命令。

## 执行顺序

1. **候选源码**：核对最新 `main`、已发布 `0.3.0`、目标版本空缺。统一十包版本、`vite` 随包 skill 版本、发布检查、版本断言、包内 README 和 CHANGELOG；核对锁文件与 diff。
2. **候选门禁**：冻结安装、lint、build、typecheck、单测、Chrome 浏览器测试、onboarding smoke、文档构建、发布检查和依赖审计。Windows 构建与回归以 GitHub CI 实跑为准；引擎与联网浏览器测试按手册记录。逐包 pack，检查内容、公开入口、依赖版本和 SHA-256，并从独立项目安装全部候选 tarball。
3. **源码交付**：审阅候选 diff，经 PR 合入 `main`；在最终合并提交运行并核对完整 CI。把 `v0.3.1` 标签固定在该提交，再从同一干净提交创建唯一的 `release/npm-0.3.1` 分支，核对远端未占用并推送。发布分支不再修改源码。
4. **npm 批量提交**：确认账号、组织权限、目标版本不存在、文档站与发布分支内容一致。按依赖顺序对十个包执行发布命令，先把整批包提交或暂存完毕，再集中核对版本与 `latest`。本次按项目所有者要求，不在每个包的命令之后做完整版本检查；这可能产生上层包已公开而下层 tarball 尚未可下载的短暂安装窗口。若 npm 要求网页批准，按依赖层次批准；同一版本显示已暂存或结果不明时只读查明状态，不盲目重发。发布期间只做避免重复提交所必需的状态核对；完整版本检查留到十包提交之后。
5. **集中读回**：十包提交完成后统一核对 npm 版本、`latest`、tarball 可下载、包内容与依赖；独立消费项目安装全部公开包并导入公开入口。任一包未公开时先定位暂存或失败状态，记录局部结果。
6. **文档与收口**：包全部公开后更新网站和仓库入口的当前版本、安装命令，运行文档检查，经 PR 合入并按文档站流程部署。写发布记录，核对 Git、npm 与文档站最终状态。

## 停止与恢复

- 必需门禁、候选 tarball 或最终 `main` CI 失败时，先修复并重新验收，不发布。
- npm 提交结果未知时先按精确包名和版本只读核对；不可覆盖已公开版本，不用 `unpublish` 回滚。
- 文档站可切回上一生产部署；npm 已公开的包只能通过后续修复版本处理。业务应用的生产验收仍独立进行。
