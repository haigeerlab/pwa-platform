# 关卡 2：公共/私有接口分类

进入条件：关卡 1 通过，且 Q9 答"需要公共运行时缓存"。Q9 答"否"时本关卡不执行：在状态文件把关卡 2 置为 `skipped` 并写明原因，`profile` 保持默认档。

目的：让**人**逐个确认哪些接口是公共读取。**默认一条都不写**：没有人的明确确认，不写任何 `public-data` 或 `navigation-public-dynamic` 规则。你不能替业务方判断接口是否公开，也不能凭名字猜，例如 `/api/catalog` 听起来像公共，但可能带用户折扣。

## 平台永远不缓存的

私有数据、写请求、流媒体和未分类的请求，默认不进入运行时缓存，规则也无法把它们加进来。带 `Authorization` 请求头的请求直接走网络。`Set-Cookie` 在 Service Worker 里读不到，平台无法据此判断内容是否公开，所以**被规则覆盖的接口不得按用户、会话或权限返回不同内容，也不应设置 Cookie**。`Vary` 只允许为空，或只含 `Accept`、`Accept-Encoding`，其余会让响应整体不入缓存。完整的准入条件见《公共读取缓存》，本文件不复制，也不另立规则。

## 步骤

1. **只读列出候选**：扫描 `fetch`、`axios`、请求封装、接口文档里的同源 `GET`，列出接口前缀。只列出，不评价。
2. **逐个提问**，每个接口一次，让人回答：
   - 是同源的 `GET` 吗？
   - 任何用户、任何登录状态下，返回的内容是否相同？
   - 会设置 Cookie 或按会话个性化吗？
   - 可以接受多旧的数据？决定用 `network-first`（在线优先，失败才用缓存）还是 `stale-while-revalidate`（先给旧数据再后台更新，仅用于 `public-data`）。动态页面（`navigation-public-dynamic`）只支持 `network-first`。
3. **等明确的肯定答复**（G3）。"都缓存吧"、"全部可以"、"你看着办"不算：要**逐个接口**确认。人说不清的接口记为"无法确认"，**不写规则**，也不因为其他接口已确认而带上它。
4. **写入状态文件**：每个接口一行，含前缀、资源类别、策略、确认日期。再写规则。
5. **限额问人**：`runtimeCache.enabled` 打开后需要 `maxEntries`、`maxEntryBytes`、`maxAgeSeconds`，**没有默认值**，让人给出，范围见《公共读取缓存》。
6. 运行生产构建，读诊断。`compile.runtime-strategy-unsupported`（类别与策略组合不受支持）改策略；`compile.runtime-cache-unused`（开了开关但没有规则落在可执行组合里）核对是否漏改了某条规则的策略。
7. 本地用 `vite preview` 看不到写入是正常的：它默认加 `Vary: Origin`，写入要到关卡 3、4 在部署地址上验证。

## 通过标准

每条 `public-data` / `navigation-public-dynamic` 规则都有对应的人工确认记录；没有确认记录的接口没有规则。

## 停止条件

- 任何接口无法确认是否公开：不写它的规则，停在该接口，其余已确认的可以继续。
- 项目是 Nuxt：Nuxt 打开运行时缓存会在构建期失败，停下说明，不要硬做。

## 结束时

状态文件关卡 2 置为 `done`（或 `skipped`），确认清单留在"决策记录"。
