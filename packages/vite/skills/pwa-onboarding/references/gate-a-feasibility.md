# 关卡 A：可行性与冲突检测

进入条件：无（第一个关卡）。目的：确认这个项目能接入，找出会与平台抢同一职责的东西，问清线上是否已经是 PWA。**全程只读**：扫描不修改文件，不运行项目。

## 1. 可行性

先读 `package.json`、锁文件、`vite.config.*`、`index.html`。

| 检查 | 通过 | 不通过时 |
| --- | --- | --- |
| Vite | 版本为 Vite ^5 或 ^8 | 停下说明，不硬做 |
| 框架 | 版本为 Vue ^3.4 或 React ^19.2（Vite 项目） | 停下说明 |
| Node.js | 22.12 及以上 | 停下说明 |
| `base` | 绝对路径，如 `/` 或 `/app/` | 相对路径（`./`、空串）不受支持，停下并让人决定 |
| 运行时缓存 | 未要求，或框架为 Vite | Nuxt 要求运行时缓存不受支持，停下 |

## 2. 冲突目录

只读静态扫描，**每一项记录文件与行号**。分三类：

| 类别 | 检测对象 | 处理 |
| --- | --- | --- |
| 必须移除 | 依赖：`vite-plugin-pwa`、`@vite-pwa/`、直接使用的 `workbox-window`、`workbox-build` 等 `workbox-*`、`sw-precache`、`sw-toolbox`。源码：`virtual:pwa-register`、`registerSW`、`navigator.serviceWorker.register`、`self.__WB_MANIFEST`。文件：项目自带的 `sw.js`、`sw.ts`、`public/manifest.*`。HTML：重复的 `<link rel="manifest">` | 给出改动清单，同一 scope 只能有一个注册。人确认（G1）后在**单独分支** `pwa-onboarding` 执行；先读旧 worker，确认业务还需要它的哪些行为 |
| 需要评估 | 其他厂商的 Service Worker（推送 SDK），尤其同一 scope；自建的版本轮询或更新提示 | 读取 [gate-a-third-party-sw.md](gate-a-third-party-sw.md)，按 scope 关系判定，交给人 |
| 仅提示 | HTML 里的 `<base>`（插件会拒绝）；构建后混淆插件的顺序与随机种子；PurgeCSS 白名单需加 `/^pwa-update-notice/`；产物根目录里文件名随构建变化的运行时配置脚本；确定性构建 | 提醒，不自动改 |

仅提示项的做法：

- **混淆插件**在 `enforce: "post"` 时，`pwa()` 要排在它之后，并使用固定的混淆种子。
- **确定性构建**：对同一源码连续构建两次，比较同名 JS、CSS 产物的哈希应相同；再改一处会进入预缓存的代码，确认 worker 随之变化。同名不同内容通常来自按当前时间生成的版本号，改成固定的发布编号，不要靠关闭文件指纹解决。
- 只在 `.vue` 文件里扫描的 PurgeCSS 会误删更新提示的样式，先对比开关它时的产物，再判断是谁的问题。

## 存量 PWA 迁移

有 `vite-plugin-pwa` 的 `VitePWA(` 调用，或人说线上已经是 PWA：`existingPwa` 记为 `true`，问是否有环境实际注册过。声称"还没上线"不能证明任意一份拷贝没上线。

迁移步骤按顺序做：

1. **先记录**现有线上行为：worker 地址与 scope、缓存名、运行时缓存、离线页、更新提示。
2. **身份字段先问清再写**：origin、scope、worker 地址、manifest ID。首次生产注册后不可变更（G2）。
3. 平台**不会自动清理旧缓存**，向人说明并请他决定是否安排清理。
4. 说明"原 worker 在所有受控标签页关闭前仍继续控制已打开的页面"，规划 worker 切换演练。
5. 不改变 worker 地址时，新 worker 替换原注册；改变时旧注册需另行处理。
6. **停下点**：**清理旧缓存**与**切换 worker** 只说明并记录，不代为执行，由人按迁移文档与恢复演练完成（G5）。安全的配置写入可以做，但仍受 G1、G2 约束。

## 通过标准

在兼容范围内；"必须移除"项已处理或人明确保留；存量情况已确认。

## 停止条件

版本或框架不受支持；`base` 是相对路径；人拒绝处理"必须移除"项且两者无法共存。**不自动删除**依赖或文件。

## 结束时

冲突清单与改动清单写入状态文件，关卡 A 置为 `done`。
