# 关卡 4：浏览器验证

进入条件：关卡 3 通过。目的：在**最终部署地址**上，由人用真实浏览器逐条验证注册、离线、更新、弱网与恢复。你不能替人操作浏览器：逐条念出步骤，让人执行并回报所见，再据此报告。

## 原则

- 步骤来源是《上线前检查》第 2 节与《恢复演练》，本文件只编号并写明"通过时应看到什么"，**不另立标准**。
- 在部署地址上验证，不用 `vite dev`：开发服务不生成平台 worker。先 `vite preview` 本地排查，再到线上重复。
- 测试时在 DevTools 的 Network 里勾选 **Disable cache**，避免 HTTP 缓存掩盖预缓存缺口。
- 没做的步骤记 `无法判定`，**不算通过**。

## 步骤

| 编号 | 主题 | 怎么做 | 通过时应看到 | 失败先回到 |
| --- | --- | --- | --- | --- |
| B1 | 注册 | 在线打开入口；Application → Service workers 等状态变为 `activated`；Application → Manifest 看 `id`、`start_url`、图标、scope | worker 地址与注册 scope 和 `pwa.config.ts` 一致；manifest 字段与配置一致 | 关卡 3（S1、S5）或关卡 1 |
| B2 | 受控 | 等到 `activated` 之后再刷新；Console 执行 `navigator.serviceWorker.controller?.scriptURL` | 得到配置的 worker 地址。平台 worker 从不调用 `clients.claim()`，完成注册的那次页面本身不会被接管，这是设计；刚激活就刷新可能落空，再刷新一次 | 关卡 3 |
| B3 | 离线重开 | Network 切到 Offline，重新打开已访问的入口；再打开一个没访问过的路由 | 已访问入口显示应用壳；未访问路由显示离线页；私有接口、写请求不返回旧数据。结束后恢复在线 | 关卡 1 |
| B4 | 更新 | 请人（由人）部署一个会改变预缓存内容的新版；在已打开的页面等待或触发检查 | 页面出现更新提示；用户点击确认之前旧版继续运行；确认后才切到新版 | 关卡 3（S1、S3） |
| B5 | 已安装的独立窗口 | 把应用安装为独立窗口，重复 B4；窗口长时间不刷新，等 `updateCheck` 间隔 | 独立窗口也出现提示；没有配置 `updateCheck` 时它不会自己发现新版，这是关卡 0 Q7 的选择 | 关卡 0 Q7 |
| B6 | 多个标签页 | 同一应用开两个标签页，在其中一个确认更新 | 另一个标签页的提示变成"请刷新"；如果业务传了 `reloadPage`，有未保存内容的页面不会被强制刷新 | 关卡 1 |
| B7 | 弱网 | 用 DevTools 的 Slow 3G 或限速，不是 Offline 开关 | 接口慢时按已配置的 `networkTimeoutSeconds` 回退；没配置就记录可接受的最长等待。弱网不同于飞行模式，Offline 开关测不出这一项；至少在承诺支持的一部手机上做一次物理断网冷启动 | 关卡 1（策略） |
| B8 | 恢复 worker | 由人在类生产环境按《恢复演练》把恢复 worker 部署到原 worker 地址 | 只清理该应用当前环境的缓存，其他应用与非平台缓存保留；页面从网络重新加载 | 关卡 6 的事故分支 |

## 真机验证（闸门 G4）

B1–B3 与 B7 的断网冷启动要在真机做。让人把结果说出来，写入状态文件：**设备**型号、**浏览器**名称、**版本**、通过的步骤编号。人没有明确回答就不要记通过。

## 通过标准

B1–B8 都有结果，没有 `不通过`，`无法判定` 项已说明原因；真机验证已获 G4 确认。

## 停止条件

任一必测步骤失败：停在该步，用报告标签写清 `实际`、`后果`、`回到哪一关`，修好后回到该步重验，不要跳过。人说"没做的步骤先不管"也只能记 `无法判定`。
