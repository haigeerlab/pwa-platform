# 为什么有 PWA Platform

业务应用想让用户安装到桌面、断网时再次打开、收到更新提示，通常要同时处理 manifest、Service Worker、缓存规则、构建产物和发布响应头。逐项目复制这套代码，会让安全边界和更新行为逐渐分叉。

PWA Platform 把这些共性能力收拢为一套声明式接入方式。业务团队描述“这个应用是谁、部署在哪里、哪些资源可以离线使用”；平台负责编译和执行规则。它是**基础设施**，不是业务应用模板，也不替应用设计界面或决定哪些业务数据是公开的。

## 面向谁

- **业务前端团队**：接入安装、离线与更新体验，声明可缓存资源。
- **平台维护者**：维护契约、策略编译、浏览器运行时和宿主适配器。
- **发布团队**：校验部署产物、响应头、旧资源保留与恢复路径。

## 设计目标

1. 用户访问过应用后，可以在离线状态重新打开已缓存的应用壳。
2. 静态资源和明确的公共读取按可评审的规则缓存。
3. 新 worker 下载完成后等待用户确认，避免无提示接管旧页面。
4. 构建期发现声明与产物不一致的问题，发布期继续核查环境事实。
